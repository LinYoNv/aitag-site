# AI绘画咒语图库站 · 建设大纲 v2（含群友上传）

> 在 v1（`OUTLINE.md`）基础上，根据**新确认的需求**修订：
> ① 测试数据直接用 AstrBot 目录里的真实 NovelAI 图；
> ② 站点最终要**开放给群友上传图片和参数**（不只是展示）；
> ③ 首期仅做 首页 + 详情页；详情页保留 prompt/参数展示。
> 版本：v0.2（待你拍板的点见「待确认」）。

## 〇、本次修订的原因

原 v1 定位是"自建展示站，先用示例数据，后接真实数据"。你补充的两个信息改变了架构：

1. **数据来源**：不再用造假的示例数据，直接从现有 AstrBot 目录导入约 10 张真实 NovelAI 图当测试数据。已验证每张 PNG 的 `tEXt/Comment` 内嵌完整参数 JSON（prompt/uc/sampler/steps/尺寸/seed 等 40+ 字段），**详情页能完整还原"咒语配方"**。
2. **产品形态**：站点的最终目的不是只给站长看，而是**开放给群友，群友上传图片和参数**。这就从"展示站"升级为"读 + 写（UGC 上传）"的图库站。

这两点叠加，数据流变成：

```
群友/内部上传图片+参数
        │  (图上传 + 贴参数 或 直接传 PNG 让后端自己读元数据)
        ▼
后端解析/校验 → 存入 SQLite(works 表) → 图片落盘 public/uploads
        │
        ▼
首页画廊/搜索 ← 读取 → 详情页展示图片+完整参数
```

## 一、站点定位（修订）

- **是什么**：面向群友开放的新图库 / 咒语检索站。
- **核心价值（不变）**：能搜到作品，点进去看那张图的完整 hint/参数（prompt、负向 prompt、sampler、seed、尺寸……），方便学习、参考、改咒语。
- **新增价值**：**群友可上传**自己的图片和参数，形成"共同积累、互相参考"的祈语库。
- **与原站关系（不变）**：结构/页面/交互形似 aitag.win，但数据是自有的、社区积累的；砍掉合规/埋点等杂质。

## 三、功能清单

**保留（原站精髓）**
1. **卡片**：1:1 方形封面 + 左上类型徽章(sd橙/nai蓝/nai_x深蓝/comfy紫) + 右上图数角标 + 左下信息层。
2. **画廊栅格**：瀑布网格，列数随屏宽 6→4→2。
3. **搜索**：作品ID / 作者 / 简介 / tags / 日期 / AI类型 / 模型；支持 `-排除`、`OR`、`"精确短语"`。
4. **Prompt 检索**：按 metadata 里的 prompt 搜（本站关键差异）。
5. **排序/时间**：`new`(最新)；时间范围。
6. **悬浮预览**：悬停卡片跟随显示标题+预览图。
7. **详情页**：图片组切换 + AI 元数据两种视图（JSON 原文 / 格式化「指令」视图）。
8. **多语言**：简体中文 + English。
9. **metdata 展示**：NovelAI PNG 内嵌的完整参数（见第六节字段表）。

**新增（群友上传）**
A. `/upload` 上传页：两种上传方式
   - ① 直接传 PNG：后端自动解析内嵌 tEXt 元数据 → 自动填参数（对 NovelAI 图最省事，推荐）。
   - ② 传图片 + 手动填表单：标题/作者/图片/SD|NAI|ComfyUI 类型/prompt/负向/参数表格。
B. 上传入口：首页 header 放「上传」按钮。
C. 防滥用（后续可收紧）：上传频率限制；暂不做登录/审核（先内部跑通）。

## 四、技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | Next.js 15（App Router）+ TypeScript | 前后端一体，同源 `/api`，适合自建 |
| 样式 | Tailwind CSS + 自定义 CSS 变量 | 快速还原深色主题 + 栅格 |
| 数据库 | SQLite（Node 24 内置 `node:sqlite`） | 零额外依赖、单文件、方便搬服务器 ✅已验 |
| 接口 | Next.js Route Handlers（同源 `/api/*`） | 与原站同源接口思路一致 |
| 图片 | `public/images/`（测试导入）+ `public/uploads/`（群友上传落盘） | 本地自建存储；留 CDN 前缀切换点 |
| 上传 | Next.js Route Handler + `formidable`（或原生 `request.formData()`） | 接收 multipart；避开需编译的原生包 |
| 部署 | `next build` → Node 运行（pm2/systemd/Docker） | 你搬到别的服务器，附部署说明 |

> 环境约束（已确认）：Node v24.19.0 内置 `node:sqlite` ✅；npm registry 可达 ✅；容器缺 C/C++ 工具链 → 所有依赖避开需 node-gyp 源码编译的原生包（选型已规避：SQLite 用内置、上传用原生 formData 或纯 JS 解析）。

## 七、上传页设计（本次核心新增）

**解析位置（已拍板）**：PNG 元数据解析**在浏览器端（前端）完成，后端不做 PNG 解析**。前端解析失败直接提示「失败」，用户改走手动填写。

**上传流程：**

1. **前端解析 PNG**：用户选择一张 PNG → 浏览器 `FileReader.readAsArrayBuffer` → 前端纯 JS 遍历 PNG chunk，抽出 `tEXt/Comment` 的 JSON → 成功则自动填 prompt/负向/参数，失败则**提示「失败」**，允许用户手动填。
2. **手动表单**：传任意图片，手动填 ai_type + prompt + 参数表格（解析失败时的兜底路径，也是非 NovelAI 图的通用入口）。
3. **提交入库**：前端把「图片二进制 + 标题 + 作者占位符 + 类型 + 已解析/手填的参数」POST `/api/upload`，后端只负责**存图 + 写库**，不再解析。

**上传侧界面**：拖拽/选择图片、预览、标题、类型下拉、prompt 大文本、参数表格（可选）。提交后跳转详情页。

**前端解析实现**：写一个纯 JS 的 PNG tEXt 解析器（浏览器端 `DataView`/`Uint8Array` 遍历 chunk，不依赖第三方包），`Comment` JSON.parse 即可——服务端已验证该字段可读，前端逻辑同源可行。
